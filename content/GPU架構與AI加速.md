# GPU 架構與 AI 加速

這篇筆記探討 GPU 在 AI 領域中作為主流加速晶片的架構演進，特別關注其如何解決平行運算與記憶體存取的挑戰。現代 GPU 從傳統圖形渲染逐漸演變為高度特化的平行運算引擎，成為訓練與推論大模型不可或缺的基石。

## 方案探討：GPU 架構演進方向

### 方案一：強化 Tensor Core 單元 (以 NVIDIA Hopper 為例)
- **優點**：極大化矩陣乘法的吞吐量，透過特製的浮點數格式（如 FP8, BF16）提升效率。
- **缺點**：電晶體數量與能耗大幅增加。
- **成本**：晶片製造成本極高。
- **維護性**：需依賴高度最佳化的軟體生態（如 CUDA、cuDNN）才能發揮硬體潛力。
- **風險**：單一供應商鎖定，導致採購與軟體遷移成本高昂。

### 方案二：擴展記憶體頻寬與容量
- **優點**：解決大型語言模型（LLM）的記憶體牆（Memory Wall）問題，使得更大規模的模型得以在單一 GPU 內載入與推論。
- **缺點**：高度依賴 [[HBM技術與記憶體牆解決方案]]，而 HBM 產能有限且良率控制困難。
- **成本**：封裝成本（如 CoWoS）與記憶體本身成本佔據晶片總成本的一大部分。
- **維護性**：硬體設計複雜，散熱與供電挑戰嚴峻。
- **風險**：受限於先進封裝產能瓶頸。

### 方案三：開放架構設計 (如 AMD CDNA 系列)
- **優點**：提供更多硬體客製化與開放軟體堆疊（ROCm），降低對單一生態系的依賴。
- **缺點**：軟體生態仍處於追趕階段，相容性與開發體驗不如業界標準。
- **成本**：硬體性價比通常較具競爭力。
- **維護性**：需要投入大量資源進行軟體層的適配與優化。
- **風險**：若軟體生態無法快速成熟，可能難以吸引足夠的開發者與企業採用。
