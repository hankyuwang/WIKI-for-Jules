# Megatron

摘要：Megatron 是 NVIDIA開源的3D平行訓練框架，專為極大規模語言模型設計，包含張量與管線平行。

## 已知事實
隨著模型參數達到數百億至數千億，單一 GPU 無法裝載完整的模型參數與優化器狀態。Megatron-LM 透過創新的張量平行 (Tensor Parallelism) 技術，有效將單一層的神經網路切割到不同的 GPU 上運算，是訓練 GPT、Llama 等大型模型不可或缺的基石。

## 原理
Megatron 運作的核心在於透過底層架構的最佳化，解決傳統架構在訓練極大規模語言模型（如 Llama）上遇到的效能與記憶體瓶頸。其核心技術主要依賴兩種平行化策略：

### 1. 張量並行 (Tensor Parallelism, TP)
張量並行是將模型中單一層的運算（例如 Attention 層或 MLP 層中的矩陣乘法）切分並分散到多張 GPU 上同時執行。
- **運作方式**：在矩陣相乘時，將權重矩陣按行或列切分，每個 GPU 計算部分結果，最後再透過通訊聚合（例如 All-Reduce 操作）得到完整輸出。
- **適用場景**：由於 TP 需要極高頻率且低延遲的節點內通訊，通常被限制在單一伺服器節點內使用，極度依賴如 NVLink 等超高速互連技術。

### 2. 流水線並行 (Pipeline Parallelism, PP)
流水線並行是將整個模型的不同層（Layers）按順序切分，分配到不同的 GPU 或節點上。例如，GPU 1 負責第 1~10 層，GPU 2 負責第 11~20 層。
- **運作方式**：前向傳播（Forward Pass）時，資料像工廠流水線一樣從一個 GPU 傳遞到下一個 GPU。為了減少因等待前一個 GPU 完成運算而產生的「管線氣泡（Pipeline Bubbles）」或是閒置時間，通常會結合微批次（Micro-batching）技術（例如 1F1B 排程：交替進行一次前向與一次反向傳播）。
- **適用場景**：PP 的通訊量較小（只需傳遞啟動值 Activations），因此適合跨節點（Cross-node）擴展，透過 RDMA 等網路技術連接。

## 限制
Megatron 的設定非常複雜，需要深厚的系統知識來調校 TP, PP, DP 的比例以達到最佳利用率。此外，極度依賴硬體的高速網路基礎設施。

## 未知問題
如何在不穩定的雲端環境中（如節點頻繁失效）實現容錯與快速恢復，以及如何與自動化編譯器（如 XLA）更緊密整合，是當前的研究熱點。

## 最佳實務
在實務上，通常會結合 DeepSpeed 的 ZeRO 優化技術（即 Megatron-DeepSpeed 框架），以在保持計算效率的同時，進一步降低記憶體佔用。

## 方案與觀點分析

### 方案一：純 Megatron 3D 平行訓練
- 優點：運算效率極高，經過 NVIDIA 原廠深度優化，穩定性好。
- 缺點：對硬體網路要求極高，缺乏彈性。
- 成本：高，需購買高階互連設備。
- 維護性：中，設定與部署門檻高。
- 風險：硬體故障導致的重訓成本高。

### 方案二：Megatron 結合 ZeRO 優化 (DeepSpeed)
- 優點：大幅減少記憶體佔用，能在有限的硬體資源下訓練更大的模型。
- 缺點：跨節點通訊量可能增加，導致效能略有下降。
- 成本：中等，可利用較普通的網路設備。
- 維護性：中，框架整合需經驗。
- 風險：記憶體換通訊的策略在網路頻寬不足時會造成嚴重瓶頸。

### 方案三：自動化平行搜尋 (Auto-Parallelism)
- 優點：透過編譯器自動尋找最佳的平行化切分策略，降低工程師手動調校的負擔。
- 缺點：搜尋空間龐大，編譯時間極長，且產出的排程可能非全局最佳。
- 成本：低（節省人力成本）。
- 維護性：高，模型變更時自動適應。
- 風險：目前技術尚不夠成熟，可能無法應對最新穎的模型架構。
