# INT4

摘要：INT4 (4-bit Integer) 是一種極端的模型量化技術，將神經網路權重壓縮至 4 位元，大幅降低模型儲存空間與記憶體頻寬需求，是大型語言模型 (LLM) 部署至邊緣設備的關鍵技術。

## 五分鐘版
隨著 LLM 動輒數十至數千億參數，記憶體容量與頻寬成為推論的巨大瓶頸（記憶體牆）。INT4 量化將原本 FP16 的權重壓縮 4 倍，使其能在記憶體較小的消費級 GPU 甚至手機上運行。最常見的實務是僅量化權重 (Weight-Only Quantization, W4A16)，保留激活值在 16-bit 以維持精度。

## 完整版
### 已知事實與原理
INT4 的值域僅有 16 個離散數值（-8 到 7）。為了能表示模型中分佈廣泛的權重，必須使用 Scale (縮放因子) 和 Zero-point (零點)。常見的技術如 GPTQ, AWQ 等，會透過校準數據 (Calibration Data) 計算最優的量化參數，以最小化量化後與原始權重的誤差。

### 限制與邊界條件
過度壓縮容易導致嚴重的精度損失，特別是在模型出現 Outliers (極端大值) 的激活層或權重分佈時。因此通常採用分組量化 (Group Quantization)，例如每 128 個權重共用一組 Scale，以在壓縮率和精度間取得平衡。

### 最佳實務
目前的開源生態中，使用 llama.cpp 搭配 GGUF 格式的 INT4 模型，或是在伺服器端使用 vLLM 搭配 AWQ 格式，已成為兼顧速度與成本的標準做法。

## 方案與觀點分析 (推論優化層面)

### 方案一：Weight-Only INT4 (W4A16)
- 優點：有效降低記憶體讀取瓶頸，推論速度顯著提升，精度損失可控。
- 缺點：矩陣運算時仍需將 INT4 解量化 (Dequantize) 回 FP16 進行計算，無法享受 INT4 專用乘法器的算力紅利。
- 成本：低（現成軟體支援）。
- 維護性：高。
- 風險：低。

### 方案二：Full INT4 (W4A4)
- 優點：權重與激活皆為 INT4，能利用硬體的 INT4 Tensor Core 達到極高的 TOPS，大幅加速運算。
- 缺點：激活值 (Activation) 量化非常困難，極易導致模型崩潰，需要複雜的 QAT (Quantization-Aware Training)。
- 成本：高（訓練成本與調研成本）。
- 維護性：低。
- 風險：極高（模型精度大幅下降的風險）。

### 方案三：混合精度量化 (Mixed Precision Quantization)
- 優點：針對敏感層保留 FP16 或 INT8，不敏感層使用 INT4，兼顧整體精度與效能。
- 缺點：硬體調度與軟體編譯器實作非常複雜。
- 成本：中高。
- 維護性：中等。
- 風險：如果硬體不支持高效的格式轉換，可能導致效能反而下降。


## 💡 初學者比喻：什麼是 INT4 量化？
想像你要記錄全班同學的身高。
- 如果你精確記錄到小數點後 5 位（比如 175.12345 公分），這就是 FP32，非常精確但需要很大的紙張空間。
- 如果你只記錄整數（175 公分），這就像是 INT8 量化，省了一半空間。
- **INT4 量化** 更極端，你只用 16 個級別來分類所有人。比如：A=150, B=155... P=225。你只需要記下每個人對應的字母，空間瞬間縮小到原本的 1/8！但缺點是，如果有人身高剛好是 152，他就會被強制歸類到 150，產生了誤差。
為了減少誤差，我們把全班「分組（Group）」：男生一組、女生一組，各自有自己的 16 個級別標準，這就是實務上極為重要的「群組量化 (Group Quantization)」。

## 深入探討：INT4 的實務細節與群組量化 (Group Quantization)
在 INT4 中，一個數值只能表示 16 個狀態（$2^4 = 16$）。如果我們對整個神經網路層使用同一組 Scale（縮放因子），極端的異常值 (Outliers) 會拉大 Scale，導致大量正常數值被擠壓到同一個狀態，造成災難性的精度損失。

為了克服這個問題，實務上廣泛採用了 **群組量化 (Group Quantization)** 或稱為 **Block-wise Quantization**：
- **原理**：我們將一長串的權重（例如 128 個權重為一個 Block）綁定在一起，共用一個 Scale 和 Zero-point。這意味著即使出現局部異常值，它也只會影響這 128 個權重，而不會波及其他群組。
- **優勢**：在保持極高壓縮率的同時，顯著降低了量化誤差，讓 INT4 甚至在一些 7B 參數別的模型上也能保持與 FP16 相近的生成品質。

## INT4 在 LLM 推理上的效能革命
在部署大型語言模型 (LLM) 時，推論的瓶頸通常在於「記憶體頻寬」，而非「運算能力」（這被稱為 Memory-Bound 狀態）。
1. **突破記憶體牆**：將模型權重從 FP16 轉換為 INT4，模型大小直接縮小近 4 倍。這使得原本需要多張高階 GPU 才能載入的模型，現在可以輕鬆塞進單張消費級顯示卡（如 RTX 4090）甚至高階筆電中。
2. **提升吞吐量**：在進行 Token 生成 (Decode 階段) 時，每個 Token 都需要讀取一次完整的模型權重。INT4 讓每次需要傳輸的資料量減少，直接加快了 Token 的生成速度，大幅改善了使用者的等待延遲 (Latency)。
