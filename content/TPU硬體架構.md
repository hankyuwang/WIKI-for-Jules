# TPU硬體架構

摘要：探討專為張量運算與機器學習設計的 TPU (Tensor Processing Unit) 及類似 ASIC 架構，分析其硬體設計理念與實作方案。

## 解決方案與架構比較

### 方案一：Systolic Array (脈動陣列) 架構
TPU 最核心的設計之一，資料在處理單元陣列中以脈動的方式流動，減少了對記憶體及暫存器的存取次數，非常適合執行龐大的矩陣乘法。

* **優點**: 極大幅度減少 SRAM 的讀寫，提供超高的運算密度與能源效率。
* **缺點**: 對於非矩陣運算 (如 Activation functions) 效率不彰，需依賴其他輔助處理單元。
* **成本**: 針對特定大小矩陣優化的設計限制了靈活性，NRE (Non-Recurring Engineering) 成本高。
* **維護性**: 中，軟體編譯器 (如 XLA) 需負責將運算圖對齊到硬體的陣列大小。
* **風險**: 硬體架構過於專一，若未來演算法不再以大型稠密矩陣乘法為主，硬體效益將大幅下降。

### 方案二：VLIW (Very Long Instruction Word) 架構
部分 TPU 架構採用 VLIW 設計來控制資料流與運算單元。編譯器在編譯階段靜態排程指令，將多個相互獨立的運算包裝在一個極長的指令中同時執行。

* **優點**: 硬體控制邏輯簡單，節省了動態排程 (如 OoO, Out-of-Order execution) 的硬體開銷，將空間留給運算單元。
* **缺點**: 極度依賴編譯器的最佳化能力；遇到快取未命中 (Cache miss) 時容易造成管線停頓 (Pipeline stall)。
* **成本**: 硬體成本較低，但軟體編譯器的開發成本極高。
* **維護性**: 較低，每次硬體架構迭代都需要大幅修改編譯器後端。
* **風險**: 若編譯器無法有效填滿 VLIW 指令槽，會造成運算資源閒置，效能大打折扣。

### 方案三：Domain-Specific Architecture (DSA) 擴展
除了核心的矩陣運算，現代 TPU (如 TPU v4/v5/Trillium (TPU v6)) 引入了更多領域特定單元，例如專用網路處理器與分散式記憶體架構 (參見 [[HBM記憶體技術]])，形成叢集級別的超級電腦。

* **優點**: 在資料中心規模下，能提供無可匹敵的總體訓練吞吐量與低延遲推論。
* **缺點**: 系統極為封閉，且擴充能力受限於專屬的網路拓樸架構 (如 Torus topology)。
* **成本**: 極端昂貴，僅適合超大型雲端服務商 (CSP) 自行研發與建置。
* **維護性**: 仰賴 CSP 內部專門團隊維運，外部開發者難以接觸底層架構。
* **風險**: 開發者必須綁定特定的雲端生態系，難以無縫遷移至其他硬體平台。
