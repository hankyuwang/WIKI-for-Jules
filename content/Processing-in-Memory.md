# PIM (Processing-in-Memory) 記憶體內運算

## 摘要
傳統的范紐曼架構在執行 AI 運算時，需要頻繁地在運算單元與記憶體之間搬移資料，導致極大的功耗與延遲（即「記憶體牆」）。PIM（Processing-in-Memory）技術直接在記憶體內部或周邊整合運算能力，從根本上減少資料搬移。本篇探討 PIM 的架構方案及其在突破算力瓶頸上的潛力。

## 方案與觀點

### 方案一：近記憶體運算 (Near-Memory Compute)
將運算單元（如簡單的 MAC 單元）整合在記憶體的邏輯層或控制器中（如 HBM 的 Base Die 或 3D 堆疊的底層邏輯晶片）。
- **優點**：架構相對成熟，不會過度干擾標準 DRAM 的製程，能有效減少外部資料傳輸。
- **缺點**：受限於邏輯晶片的面積與散熱，能提供的算力上限較低。
- **成本**：相比傳統記憶體增加了一些邏輯電路的製造成本。
- **維護性**：軟體生態系需要特定的編譯器與 API 來識別並卸載任務至近端運算單元。
- **風險**：若上層應用無法有效拆分運算與儲存任務，此架構帶來的效能提升將十分有限。

### 方案二：記憶體內運算 (In-Memory Compute)
將基本的運算邏輯直接整合進 DRAM 或 SRAM 的儲存單元（Cell Array）內部，讓資料「原地」完成運算。
- **優點**：提供了理論上最極致的記憶體頻寬與最低的功耗。
- **缺點**：嚴重破壞了高密度 DRAM 的標準結構，導致記憶體容量密度大幅下降。
- **成本**：研發與製造成本極高，且難以享有標準記憶體的大規模量產優勢。
- **維護性**：目前的軟體堆疊（如 PyTorch/TensorFlow）完全無法直接對接這種底層硬體，需要全新的程式設計典範。
- **風險**：屬於非常前沿的研究領域，商業化落地難度極大。

### 方案三：類比記憶體內運算 (Analog PIM)
利用非揮發性記憶體（如 RRAM, MRAM 或 Flash）的物理特性（如電阻值），透過歐姆定律和基爾霍夫定律直接在類比域完成矩陣乘法運算。
- **優點**：運算速度極快且功耗趨近於零，非常適合邊緣設備的低功耗推論。
- **缺點**：類比運算存在雜訊與精度損失（通常難以達到 FP32/FP16，甚至 INT8 也受環境溫度影響）。
- **成本**：依賴新興記憶體材料的製程成熟度。
- **維護性**：ADC/DAC（類比數位轉換器）的設計是系統瓶頸，且需要考慮裝置的老化與漂移效應。
- **風險**：目前精度難以滿足主流 LLM 的需求，多限於極特定的小型視覺或語音喚醒模型。
