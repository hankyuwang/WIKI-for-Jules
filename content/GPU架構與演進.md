# 摘要

圖形處理器（GPU）最初專為加速電腦圖形渲染而設計，但其高度平行運算的特性使其成為深度學習與人工智慧（AI）領域的核心硬體。GPU 架構歷經多次演進，從早期的固定管線發展到可程式化的統一著色器架構（如 NVIDIA 的 Tesla、Fermi、Kepler、Pascal、Volta、Ampere 到目前的 Hopper 及 Blackwell）。現代 GPU 針對 AI 任務優化，引入了 Tensor Core 等專用硬體單元以加速矩陣運算，並大幅提升記憶體頻寬。本文章探討 GPU 應用於 AI 運算時的三種架構與佈署觀點，並分析其優缺點及風險。

## 方案一：單機多卡 (Single-Node Multi-GPU) 部署架構

此方案在單一伺服器節點內安裝多張 GPU（例如 4 或 8 張），透過 PCIe 或是高速互連技術（如 NVLink）進行資料交換。這種架構常被用於模型訓練與中等規模推理任務。

### 優點 (Pros)
- **容易佈署**：相較於分散式叢集，單一節點的管理與維護較為簡單。
- **高頻寬互連**：節點內的 GPU 透過 NVLink 或 PCIe 互連，可提供極高的資料傳輸速率與低延遲，適合參數同步。
- **軟體生態系成熟**：多數 AI 框架（如 PyTorch、TensorFlow）原生支援單機多卡的資料平行與模型平行訓練。

### 缺點 (Cons)
- **擴充性受限**：受限於單一伺服器的電源、散熱與 PCIe/NVLink 拓樸，最多只能容納有限數量的 GPU（通常為 8 或 16 張）。
- **單點故障風險**：若伺服器主機板或電源發生故障，整個節點的運算能力將完全停擺。

### 成本 (Costs)
- **初期建置成本適中**：購買高階多 GPU 伺服器的成本雖高，但相較於建立具備高速網路（如 InfiniBand）的叢集，總體成本較低。

### 維護性 (Maintainability)
- **高維護性**：硬體更新、軟體升級與驅動程式管理皆可在單一機器上完成，維護難度較低。

### 風險 (Risks)
- **資源瓶頸**：在大型模型（如千億參數 LLM）訓練時，單機記憶體總量可能不足以容納模型權重與優化器狀態。

## 方案二：分散式 GPU 運算叢集 (Distributed GPU Cluster)

當單一節點無法滿足巨大模型（如 GPT-4 等級）的訓練需求時，必須將數十至數千個 GPU 節點透過高速網路（如 InfiniBand 或是 RoCE）串接成一個龐大的運算叢集。這需要複雜的平行化策略（如 3D 平行化：Data、Tensor、Pipeline Parallelism）。

### 優點 (Pros)
- **極致擴充性**：理論上可無限制地擴充運算資源與記憶體總量，是訓練超大型基礎模型的唯一途徑。
- **容錯能力**：透過檢查點 (Checkpointing) 與叢集管理系統，叢集能在部分節點失效時繼續運作或快速恢復。

### 缺點 (Cons)
- **網路延遲瓶頸**：節點間的網路通訊延遲遠高於節點內的 NVLink，若平行化策略設計不當，網路通訊將成為嚴重的效能瓶頸。
- **管理極度複雜**：需要專業的基礎架構團隊來管理叢集、排程任務並處理硬體故障。

### 成本 (Costs)
- **極高建置與營運成本**：除了數千張高階 GPU 外，還需投入巨額資金於高速網路設備、資料中心散熱系統及高昂的電費。

### 維護性 (Maintainability)
- **低維護性**：硬體故障率隨節點數增加而上升，軟體除錯與效能調校極具挑戰性。

### 風險 (Risks)
- **Straggler Effect（落後者效應）**：在同步訓練中，最慢的 GPU 節點會拖慢整個叢集的訓練速度，需依賴強健的負載平衡機制。

## 方案三：雲端 GPU 實例 (Cloud GPU Instances)

透過公有雲服務提供商（如 AWS、Google Cloud、Azure）租用 GPU 運算資源，而非自建資料中心。使用者可依需求動態開啟或關閉 GPU 實例。

### 優點 (Pros)
- **高彈性與敏捷性**：無需前期硬體採購，可根據專案需求隨時擴展或縮減運算資源。
- **免除硬體管理**：硬體維護、散熱、電源等底層基礎建設問題皆由雲端服務商處理。

### 缺點 (Cons)
- **長期成本較高**：若需全年無休進行大量運算，長期租用雲端 GPU 的總成本通常會超過自建地端基礎架構。
- **資源可用性與鎖定 (Vendor Lock-in)**：在 GPU 缺貨潮時可能無法租到所需數量的運算資源，且高度依賴特定雲端服務商的生態系與計費模式。

### 成本 (Costs)
- **按需付費 (Pay-as-you-go)**：初期資本支出（CapEx）極低，但轉為持續性的營運支出（OpEx），需仔細監控以避免預算超支。

### 維護性 (Maintainability)
- **極高維護性（對使用者而言）**：僅需管理軟體環境與容器，不需處理底層硬體與網路實體維護。

### 風險 (Risks)
- **資料安全與合規性**：將敏感的訓練資料（如醫療影像、金融數據）上傳至公有雲可能面臨資安風險與法規限制。
