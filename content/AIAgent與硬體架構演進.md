摘要
本文探討從早期的 Vibe Coding（依賴直覺與反覆嘗試的輔助開發模式）到現代自主 AI Agent（如 Hermes、Claude Code、Codex、Jules 等）技術的演進過程，以及此一轉變對底層硬體支援需求帶來的深遠影響。在全面邁入 Agent 時代的背景下，AI 模型的運作模式從單次請求-回應轉向長時間的狀態保持、多步驟推理與工具調用。這促使 AI 加速晶片在軟硬體架構上發生變革，以支援低延遲推論、龐大的狀態上下文存取、以及複雜的任務切換。

## 從 Vibe Coding 到 AI Agent 的演進

在「Vibe Coding」時期，開發者依賴對大型語言模型的直覺提示（Prompting），透過反覆的對話微調來生成程式碼。此時模型主要扮演「智慧自動補全」或「問答助理」的角色，任務單一且生命週期短暫。

隨著技術發展，如 Codex、Claude Code、Hermes 與 Jules 等 **AI Agent** 相繼問世，系統具備了「自主規劃（Planning）」、「工具調用（Tool Use）」與「自我反思（Self-reflection）」的能力。Agent 不僅能生成程式碼，還能主動操作終端機、讀寫檔案、甚至編譯與測試程式碼，完成了從「輔助工具」到「數位軟體工程師」的典範轉移。

## 硬體支援需求的變化

1. **超長 Context Window 與記憶體壓力**
   AI Agent 必須在執行多個任務步驟中保持長期記憶。這導致狀態上下文的容量需求急遽攀升，對記憶體頻寬與容量產生巨大壓力。
2. **低延遲（Low Latency）與高頻次互動**
   Agent 頻繁呼叫外部工具並等待結果，推論過程變得高度互動。現今的硬體需求更傾向於降低單次生成的延遲，而不僅僅是追求極致的吞吐量。
3. **動態資源分配與狀態切換**
   Agent 經常在不同模型或不同任務狀態間切換（例如：從理解規劃切換到程式碼生成），需要硬體支援極速的狀態切換與靈活的運算資源排程。

## 加速晶片軟硬體架構的三種應對方案與觀點

為支援全面使用 AI Agent 的需求，加速晶片架構正朝以下三種方向演進：

### 方案一：超大 SRAM 與記憶體內運算 (Processing-in-Memory) 架構
透過在運算單元旁配置極大容量的 `[[SRAM]]`，或直接採用 `[[PIM]]` 將運算單元整合至記憶體中，以解決狀態上下文頻繁存取的記憶體牆問題。
- **優點 (Pros)**: 極大幅度降低資料搬移延遲，提供 Agent 運作所需的極高記憶體頻寬，有效提升低延遲互動效能。
- **缺點 (Cons)**: SRAM 面積成本極高，限制了單一晶片的總容量；記憶體內運算的製程成熟度與標準化仍在發展中。
- **成本 (Costs)**: 晶片製造成本與研發成本極高，且良率挑戰大。
- **維護性 (Maintainability)**: 軟體編譯器需針對全新的運算架構重新開發與優化，軟體生態系維護難度高。
- **風險 (Risks)**: 專為特定運算模式最佳化的硬體可能因演算法架構的快速演進而面臨淘汰風險。

### 方案二：異質運算與 Chiplet 先進封裝架構
利用 `[[Chiplet]]` 技術與 `[[AdvancedPackaging]]`，將專司邏輯推理的 CPU/NPU、負責平行運算的 `[[GPU]]` 以及高速 `[[HBM]]` 封裝在同一基板上，形成針對 Agent 工作流程高度定制的異質系統。
- **優點 (Pros)**: 可靈活搭配不同的運算單元，完美契合 Agent 在規劃、生成與驗證等不同階段所需的多元運算特性，同時透過 HBM 提供充沛的記憶體頻寬。
- **缺點 (Cons)**: 封裝技術難度高，晶片間的互連（Interconnect）可能成為新的瓶頸，導致散熱與功耗問題。
- **成本 (Costs)**: 先進封裝（如 CoWoS）產能受限且價格昂貴，整體硬體建置成本高昂。
- **維護性 (Maintainability)**: 由於硬體模組化，個別 Chiplet 的升級相對容易，硬體生命週期較具彈性，降低了整體系統汰換的壓力。
- **風險 (Risks)**: 高度依賴少數具備先進封裝能力的晶圓代工廠，存在供應鏈斷鏈或產能不足的風險。

### 方案三：軟硬體協同排程與異質記憶體池化
透過軟體演算法配合硬體的動態排程，並結合 `[[CXL]]` 技術實現記憶體池化（Memory Pooling），以動態分配記憶體資源來應對 Agent 不可預測的長上下文需求。
- **優點 (Pros)**: 能夠以較低的硬體成本顯著提升記憶體資源的利用率，解決單一節點記憶體容量不足的問題。
- **缺點 (Cons)**: 跨節點或跨設備存取記憶體會引入額外的網路與協議延遲，可能影響 Agent 的即時互動效能。
- **成本 (Costs)**: 硬體擴展成本相對可控，但需要投入大量資源開發支援記憶體池化的高效排程軟體。
- **維護性 (Maintainability)**: 基於標準化的 CXL 協議，硬體擴充具有高度相容性，且軟體層級的資源管理與除錯相對容易。
- **風險 (Risks)**: 軟硬體協同排程的複雜度極高，若資源分配不當可能導致嚴重的延遲抖動（Jitter），影響 Agent 運作的穩定性。
