# OneAPI

## Prerequisites
- [[基礎計算機結構]]


摘要：OneAPI 是由 Intel 提出的一項開放且跨架構的程式設計模型與軟體框架。其核心目標是打破目前硬體專有編程模型（如 NVIDIA 的 [[CUDA]]）所造成的「硬體鎖定」生態，讓開發者只需編寫一次程式碼，就能在各種異質運算硬體（包含 CPU、GPU、FPGA 等）上高效執行。

## 解決的核心痛點
在異質運算時代，系統中通常混合了多種不同的處理器。過去，針對每種硬體，開發者必須學習和使用不同的語言與工具鏈。這導致程式碼維護成本極高，且難以將應用程式轉移到其他廠商的硬體上。OneAPI 的願景正是提供一個統一的標準來解決這個碎片化問題。

## OneAPI 的核心元件
1. **Data Parallel C++ (DPC++) 語言**：基於現代 C++ 標準並結合 SYCL 標準所發展而來。它允許開發者在標準 C++ 程式碼中同時描述資料的平行化邏輯，並且在編譯階段能夠針對目標硬體生成對應的機器碼。
2. **OneAPI 基礎函式庫**：提供一套豐富的跨架構函式庫，如 oneDNN (神經網路底層操作)、oneMKL (高效能數學運算庫) 等。
3. **工具鏈與分析器**：提供如 Intel VTune Profiler 等強大的效能分析工具，幫助開發者找出跨架構程式碼中的效能瓶頸。

## 業界影響與挑戰
Intel 推動 OneAPI 是為了一個開放的產業標準。透過開源的編譯器後端，DPC++/SYCL 程式碼甚至已經可以編譯並在 NVIDIA 和 AMD 的 GPU 上運行，同時 Intel 提供了 `dpct` 相容性工具，能夠協助將現有的 CUDA 程式碼轉換為 DPC++。然而，CUDA 生態系已經深植於機器學習領域，要說服開發者完全轉向 OneAPI 仍需要時間。

## 方案與觀點分析

### 方案一：全面遷移至 OneAPI (DPC++) 生態
- 優點：實現 Write Once, Run Anywhere，打破硬體廠商鎖定，增加採購彈性。
- 缺點：短期內需投入大量資源重構現有基於 CUDA 的代碼。
- 成本：高
- 維護性：長期極高
- 風險：效能在特定硬體上可能不如原生 SDK。

### 方案二：採用雙軌制並行開發 (CUDA + OneAPI)
- 優點：核心高效能模組保留 CUDA，新功能採用 OneAPI 以增加未來靈活性。
- 缺點：維護兩套程式碼庫，增加團隊負擔。
- 成本：中高
- 維護性：中等
- 風險：資料交換可能產生額外開銷。

### 方案三：依賴更高階的 AI 框架 (如 PyTorch) 屏蔽底層差異
- 優點：開發者只需關注框架 API，底層由框架開發商去適配。
- 缺點：適用於模型開發，但不適用於需要自行開發底層算子的進階團隊。
- 成本：低
- 維護性：高
- 風險：受限於高階框架的支援度。


## 💡 初學者比喻與深入解析
想像你想在不同的國家（不同的硬體，如 CPU, GPU, FPGA）舉辦同一場演唱會。傳統上，你需要為每個國家找不同的翻譯團隊（不同的軟體語言和框架，如 [[CUDA]] 只能用於 NVIDIA GPU）。OneAPI 就像是一個「超級通用翻譯機」，你只要寫一次企劃書，它就能幫你翻譯並部署到所有不同的國家。

### OneAPI 的戰略意義
Intel 推出 OneAPI 的核心目的是打破 NVIDIA 在 AI 軟體生態系上的壟斷地位。
- **SYCL**：OneAPI 的核心是基於 SYCL 標準，允許開發者使用單一的 C++ 程式碼基礎來針對各種加速器進行編程。
- **跨平台兼容性**：不僅支援 Intel 自家的硬體，也能透過外掛支援 NVIDIA 或 AMD 的硬體。
對於尋求多硬體供應商策略（Multi-vendor strategy）的企業而言，這是擺脫單一生態系綁定的重要嘗試。
