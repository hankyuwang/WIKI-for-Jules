# AI 加速晶片全景探索

本篇筆記旨在全面分析當前主要的 AI 加速晶片，涵蓋雲端與邊緣運算場景。我們將深入探討其硬體特性、適用模型、SDK 生態系統，並針對新創公司提出晶片選型與開發策略。

## 主要 AI 加速晶片分析

### NVIDIA H100 (雲端/訓練與推論)
- **使用場景**: 大規模 LLM 訓練、高效能推論伺服器、科學運算。
- **硬體特性**: 基於 Hopper 架構，支援 FP8 運算與 Transformer Engine，具備極高的記憶體頻寬 (HBM3) 與運算吞吐量。
- **關聯模型**: GPT-4, Llama 3 (70B+), 擴散模型等超大參數模型。
- **SDK 生態系統**: CUDA 生態系無可匹敵，cuDNN, TensorRT, Triton 等工具鏈極度成熟，對開發者最友善。

### Google TPU v5p (雲端/訓練與推論)
- **使用場景**: Google Cloud 生態內的模型訓練與推論，追求高性價比的運算資源。
- **硬體特性**: 高度優化的矩陣乘法單元，透過 OCI (Optical Circuit Switches) 實現高效的 Pod 級別互連，適合極大規模的分散式訓練。
- **關聯模型**: Gemini, Gemma, 以及依賴 JAX/TensorFlow 的模型。
- **SDK 生態系統**: 深度綁定 JAX, TensorFlow, PyTorch/XLA，生態系較為封閉但對於支援的框架效能極佳。

### Apple ANE (Apple Neural Engine) (邊緣/推論)
- **使用場景**: iPhone, iPad, Mac 設備上的本地端 AI 應用 (如: 影像處理, 語音辨識, 輕量級 LLM 推論)。
- **硬體特性**: 高效能低功耗，與 CPU/GPU 共享統一記憶體架構 (Unified Memory)，適合低延遲推論。
- **關聯模型**: MobileNet, Whisper, 輕量級的 Core ML 模型。
- **SDK 生態系統**: Core ML 框架，提供友善的轉換工具將 PyTorch/TensorFlow 模型轉換至 Apple 設備執行，但缺乏底層硬體控制權。

### Groq LPU (Language Processing Unit) (雲端/超低延遲推論)
- **使用場景**: 追求極致低延遲的 LLM 推論服務。
- **硬體特性**: 單核心架構 (Single-core architecture)，採用大量的 SRAM 以極小化記憶體存取延遲，放棄 HBM 的大容量，換取確定性的執行時間。
- **關聯模型**: Llama 3 (8B/70B), Mixtral 等 LLM 模型。
- **SDK 生態系統**: Groq 自己的編譯器與軟體棧，針對特定模型進行高度優化，開發者主要透過 API 接入。

## 邊緣運算的挑戰
邊緣端 AI 面臨著功耗 (Power)、散熱 (Thermal)、以及記憶體頻寬 (Memory Bandwidth) 的嚴格限制。此外，模型大小與邊緣設備有限的 SRAM/DRAM 之間的矛盾，促使了 [[模型量化技術]] (如 INT8, INT4, 甚至更低位元量化) 的廣泛應用。異質運算 (CPU+GPU+NPU) 的協同排程也是邊緣端的技術難點。

## 新創公司的晶片選型與開發策略

對於資源有限的新創公司，以下提供三種 AI 晶片應用策略：

### 方案一：全面擁抱 NVIDIA 雲端生態
- **優點**: 開發速度最快，開源模型與程式碼的相容性最高，減少踩坑時間。
- **缺點**: H100 算力成本極高，長期營運負擔大，容易受限於 GPU 供應鏈。
- **成本**: 極高 (雲端租用或購買硬體)。
- **維護性**: 極高 (生態系成熟，人才易尋)。
- **風險**: 成本失控，且無硬體護城河。

### 方案二：採用雲端 TPU / Groq 等替代算力
- **優點**: 針對特定場景 (如 LLM 推論) 可獲得更低的延遲或更優的性價比 (TPU)。
- **缺點**: 生態系不如 CUDA 豐富，模型遷移或優化可能需要額外的工程投入 (例如轉移至 JAX 或適應 Groq 的限制)。
- **成本**: 中等 (通常比 H100 具備更好的性價比)。
- **維護性**: 中等 (需要特定領域的工程經驗)。
- **風險**: 平台綁定風險，若模型架構劇烈改變，可能需要重新適應硬體。

### 方案三：專注邊緣端部署 (Apple ANE / 邊緣 NPU)
- **優點**: 隱私保護，無需雲端伺服器成本，可實現離線應用。
- **缺點**: 模型能力受限於邊緣算力，需投入大量精力進行模型壓縮與量化。
- **成本**: 低 (利用使用者設備的算力)。
- **維護性**: 較低 (需針對不同設備進行適配與優化，如 iOS/Android 雙平台)。
- **風險**: 若競品提供更強大的雲端體驗，邊緣端模型可能在體驗上落後。
