# 摘要
圖形處理器 (Graphics Processing Unit, GPU) 是一種專為平行處理設計的微處理器。在人工智慧與深度學習領域，GPU 憑藉其數千個核心的架構，能夠高效地處理大規模的矩陣運算，成為訓練與推論 AI 模型的核心硬體。本文將探討 GPU 在 AI 加速上的三種優化與部署方案，分析其優缺點、成本與風險。

## 方案一：單機多卡 (Single-Node Multi-GPU) 部署架構
透過在單一伺服器內部署多張 GPU (例如 4 卡或 8 卡配置)，利用 PCIe 或 NVLink 進行高速資料交換，適合中大型模型的訓練與微調。

- **優點**：架構相對簡單，資料通訊延遲較低，開發與除錯過程與單卡差異不大。
- **缺點**：擴展性受限於單一伺服器的硬體上限 (如電源、散熱與 PCIe slot 數量)。
- **成本**：硬體建置成本高昂，且需配備高等級的主機板與電源供應器。
- **維護性**：單機環境維護相對容易，軟體與驅動程式環境較易保持一致。
- **風險**：當模型規模超過單機記憶體上限時，將無法直接運作，需面臨硬體升級的瓶頸。

## 方案二：分散式叢集 (Distributed GPU Cluster) 架構
將多台配備 GPU 的伺服器透過高速網路 (如 InfiniBand 或是 RoCE) 連接，組成龐大的運算叢集，專為訓練超大型語言模型 (LLM) 所設計。

- **優點**：具備極佳的橫向擴展能力，理論上算力可無限疊加以應對龐大模型。
- **缺點**：網路通訊往往成為效能瓶頸，需依賴複雜的平行策略 (如 Data, Tensor, Pipeline Parallelism)。
- **成本**：極高的建置與營運成本，包含昂貴的高速網路設備、冷卻系統與龐大的電費支出。
- **維護性**：叢集維護極其困難，需專業的 SRE 團隊處理節點故障、網路異常與軟體同步問題。
- **風險**：若分散式調度演算法不佳或網路出現壅塞，將導致 GPU 閒置 (Idle)，大幅降低投資回報率 (ROI)。

## 方案三：雲端 GPU 實例與 Serverless 架構 (Cloud GPU & Serverless)
不自建硬體，而是利用公有雲平台 (如 AWS, GCP, Azure) 提供的 GPU 資源，甚至採用 Serverless GPU 推論服務，按需計費。

- **優點**：前期資本支出 (CAPEX) 為零，隨取隨用，彈性極高，適合需求波動大或初期探索的應用場景。
- **缺點**：長期且持續的大規模運算下，總體擁有成本 (TCO) 通常遠高於自建機房，且可能受限於雲端平台網路頻寬。
- **成本**：短期營運支出 (OPEX) 低且可控，但長期連續使用費用高昂。
- **維護性**：硬體與底層基礎設施由雲端供應商負責，企業端硬體維護負擔極低。
- **風險**：可能面臨特定高階 GPU 型號一機難求的問題，且將敏感資料傳輸至雲端可能有資安與法規合規性的疑慮。
