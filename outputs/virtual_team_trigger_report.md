# AI 虛擬團隊觸發報告：深度學習運算原理

## 觸發背景
維護員（Maintainer）在巡檢 `content/` 目錄時，發現多處檔案（如 `NPU架構探索.md`、`模型量化技術.md`、`AI加速晶片全景探索.md`）包含指向 `[[深度學習運算原理]]` 的失效連結。為了補全知識庫的完整性，維護員啟動了虛擬團隊協作流程。

## 團隊協作紀錄

### 1. 接待員 (Receptionist)
- **Goal**: 補全 `[[深度學習運算原理]]` 的 Wiki 頁面，修復現有知識庫中的失效連結。
- **Scope**: 涵蓋深度學習的核心運算（如矩陣乘法、卷積）、硬體加速的基礎，以及軟硬體協同的觀點。
- **Non-goal**: 不涉及具體特定型號晶片（如 TPU, H100）的微架構細節（由其他專門頁面涵蓋）。不深入特定模型的訓練細節。
- **Assumptions**: 讀者具有基本的計算機科學知識，但可能不熟悉深度學習硬體加速。
- **Expected Output**: 一份遵循 `instructions.md` 規範的 Markdown 文件，包含摘要、基礎概念，以及三種不同的架構解決方案/觀點。
- **Learning Level**: Intermediate

### 2. 知識架構師 (Knowledge Architect)
- **Metadata**: `level: intermediate`, `tags: [DeepLearning, Computing, Hardware, Architecture]`
- **目錄結構**: `content/深度學習運算原理.md`
- **知識組織**: 需要包含摘要（必須）、前置知識（連結到基礎計算機結構等）、基礎運算概念（GEMM, Convolution）、三種運算架構觀點（CPU, GPU, 專用加速器）及其優缺點分析。
- **雙向連結策略**: 必須能被 `[[NPU架構探索]]`、`[[模型量化技術]]`、`[[AI加速晶片全景探索]]` 參照。

### 3. 研究員 (Researcher)
- **探索結果**:
  - **已知事實**: 深度學習主要由大量的線性代數運算（特別是矩陣乘法 GEMM）構成。這些運算具有高度的平行性。
  - **核心原理**: 探討為何深度學習需要特殊硬體（記憶體牆、運算密度）。
  - **三種觀點/方案**:
    1. **通用處理器 (CPU) 觀點**: 靈活性高，但平行運算能力有限。
    2. **圖形處理器 (GPU) 觀點**: 高度平行，SIMT 架構，適合處理龐大但結構單一的矩陣運算。
    3. **專用加速器 (ASIC/NPU) 觀點**: 如 Systolic Array，專為深度學習定製，效能/功耗比最佳。
- 提出了包含優缺點、成本、維護性與風險的詳細分析。

### 4. 驗證員 (Validator)
- **驗證項目**:
  - 檢查運算原理是否符合業界共識。
  - 確認三種觀點的優缺點分析具有客觀性，無幻覺。
  - 確保不包含猜測性語氣（如「可能」、「應該」）。
- **驗證結果**: 內容事實正確，不同架構的特性對比（如靈活性 vs 功耗比）符合當前硬體設計的常理，可提交給教育員。

### 5. 教育員 (Educator)
- **轉譯與排版**:
  - 確保文章開頭有「摘要」段落。
  - 加入 YAML frontmatter。
  - 將技術內容轉化為由淺入深的結構（基礎概念 -> 架構觀點）。
  - 正確使用 Markdown 和 `[[WikiLink]]`。
- **產出**: 準備好寫入 `content/深度學習運算原理.md`。
